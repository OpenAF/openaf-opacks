# JavaScript library refresh — 2026-09-20

The refreshed opacks bundle their runtime assets locally. Upstream npm archives were checked against their published integrity digests; each changed opack records the versions and source archives in `upstream.json`. Package versions are `20260920` and file inventories/hashes are regenerated with `opack genpack .`.

Docsify's remote Google Fonts imports were removed; its themes use local font fallbacks. Asciidoc's HTTP wrapper disables remote webfonts. User-authored remote images, recordings, diagram icon services, or optional plugins that contact external services must still be configured with local resources.

## Reviewed without replacing

- **PEG:** retains the existing OpenAF-compatible Peggy 4.2.0 bundle. Peggy 5.1.0 loads, but generating a parser fails on class syntax in Rhino. Existing arithmetic, JSON and ActionsPlugin checks pass with 4.2.0.
- **AsciiMo:** `lib_asciimo.js` is a locally adapted legacy implementation with OpenAF ZIP font loading. Replacing it with a Node/browser package would remove that integration.
- **Badgen:** `badgen.js` is explicitly rewritten for OpenAF, rather than a vendored npm bundle.
- **D3SVG:** local SVG generation inspired by D3; no bundled D3 dependency.
- **KaTeX's Showdown adapter and asciinema's embedding helper:** local integration code, preserved.

## Comparison with `../openaf`

- Core already bundles **jQuery 3.7.1**; inBrowser consumes it without adding a second copy.
- Core already bundles **Chart.js 4.5.1**. It cannot replace inBrowser's 2.x bundle without migrating the public chart options.
- Core's **highlight.js 11.4.0** was updated to **11.12.0** in `../openaf/js/highlight.js`, preserving all 43 existing language grammars (45 total). Its source/provenance note is `../openaf/docs/highlight-js.md`. Asciidoc keeps its own compatible bundle for use with older OpenAF installations.
- Core contains parsers generated by Peggy, not the Peggy generator. They do not replace the PEG opack.
- The other refreshed libraries are not bundled in core. Core's Mermaid/KaTeX registration points to the optional opacks.
- Other core-only libraries were outside this opack refresh. No broad core dependency migration was performed. The core source update requires a normal OpenAF rebuild before distribution; the installed JAR was not modified.

## Validation

The reusable regression script generates a real Docsify static export using OpenAF, then tests it in headless Chrome. It also checks OpenAF Compromise/Asciidoctor execution, Mermaid SVG rendering, KaTeX with local fonts, asciinema playback, Chart.js, Ace JSON mode/theme, context menus and highlighting. HTTP requests outside its temporary local server are blocked and cause failure. Missing assets and browser exceptions also cause failure.

Prerequisites: `oaf`, Python 3, Node.js, Playwright and Google Chrome. Set `OPENAF_JAR` to the same runtime used by `oaf`. `PLAYWRIGHT_MODULE` may specify an absolute module path when Playwright is not installed locally.

```sh
OPENAF_JAR=/path/to/openaf.jar \
OPENAF_SOURCE=../openaf \
node .github/tests/external-javascript.cjs
```

This checks representative offline runtime paths, not every optional upstream feature or every browser. Downloads are only needed for maintenance; the distributed opacks include the runtime assets.
